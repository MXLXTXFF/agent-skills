# Cross-Session Task Contract Management

**Триггер применения:** работа в проекте с разделёнными по сервисам чат-сессиями (например, фронтенд и бэкенд), когда решение текущей задачи требует функционала смежного сервиса; создание, чтение или обновление файлов `*_SYNC.md`.

## 1. Именование и структура файлов синхронизации
* **Формат именования:** Файлы контрактов создаются в корне рабочей директории, ведутся строго на английском языке в формате Markdown и именуются по целевому сервису-получателю задач.
* **Идентификация файлов:** 
  * Задачи, адресованные фронтенду, записываются в файл `FRONTEND_SYNC.md`.
  * Задачи, адресованные бэкенду, записываются в файл `BACKEND_SYNC.md`.
* **Базовая шапка:** Каждый файл содержит зафиксированную краткую вводную строку на английском языке с описанием назначения файла. Это необходимо для сохранения контекста при старте новых чат-сессий или смене модели.
* **Версионирование:** Файлы синхронизации разрешено индексировать и отправлять в Git-репозиторий.

## 2. Границы ответственности
* **Запрет на работу вне домена:** Нейросеть ограничена созданием и редактированием кода только в пределах своего сервиса. Выполнение работы за другую чат-сессию категорически запрещено.
* **Доступ на чтение:** Разрешено считывать файлы кода, конфигурации и логи смежного сервиса исключительно для анализа контекста, выявления причин ошибок и формирования корректной задачи.

## 3. Постановка задач для смежной сессии
* **Формирование задачи:** Если для работы текущего сервиса требуется функционал смежного сервиса, нейросеть записывает атомарную задачу в файл синхронизации соответствующего сервиса.
* **Формат записи:** Задачи записываются в формате чекбоксов с техническим описанием требований, входных и выходных данных или параметров эндпоинтов.
* **Чистота содержания:** В файлах синхронизации запрещено размещать архитектурную документацию, описания проектов и служебный текст. Вся базовая информация хранится строго в `README.md` и `AGENT.md`.

## 4. Выполнение и актуализация задач
* **Обработка входящих задач:** При выполнении работы нейросеть проверяет предназначенный для её сервиса файл синхронизации и берет задачи в реализацию.
* **Удаление после выполнения:** После полного завершения и проверки задачи она незамедлительно удаляется из файла синхронизации.
* **Состояние без задач:** Если все задачи выполнены, в файле остается только базовая описательная шапка.
