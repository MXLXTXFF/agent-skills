# On-Demand Refactoring and Code Optimization

**Триггер применения:** прямой запрос пользователя на комплексный аудит, рефакторинг или оптимизацию существующего кода.

## 1. Регламент активации и этапы работы
* **Условие запуска:** Протокол активируется строго по прямому запросу пользователя на проведение комплексного аудита или рефакторинга.
* **Фиксация базового состояния:** Перед началом любых изменений проводится запуск существующих тестов и проверка работоспособности системы в Docker-окружении для подтверждения стабильности исходного кода.
* **Двухэтапный процесс:**
  * Первый этап: Глубокий анализ кодовой базы и формирование детального плана изменений без редактирования файлов.
  * Второй этап: Реализация правок строго после явного подтверждения и согласования плана пользователем.

## 2. Структура предварительного плана
План формируется строго с разделением на три категории:
* **Рефакторинг:** Декомпозиция модулей, устранение дублирования кода, удаление неиспользуемых конструкций, улучшение читаемости и стандартизация структуры проекта.
* **Безопасность:** Проверка устойчивости к инъекциям, валидация входных данных, аудит механизмов авторизации, проверка зависимостей на уязвимости и исключение утечек конфигурационных данных.
* **Эффективность:** Устранение узких мест в производительности, оптимизация запросов к базе данных, снижение потребления ресурсов памяти и процессора, ускорение работы логики и сборки контейнеров.

## 3. Правила реализации и коммиты
* **Сохранение контрактов:** В процессе изменений сохраняется существующая функциональность и интерфейсы сервиса, если иное не согласовано в утвержденном плане.
* **Раздельные коммиты по фазам:** Каждая категория плана реализуется и фиксируется отдельным локальным коммитом с соответствующим типом изменений:
  * Правки структуры и читаемости фиксируются с типом `refactor:`
  * Закрытие уязвимостей фиксируется с типом `fix:`
  * Улучшения производительности фиксируются с типом `perf:`

## 4. Метрики изменений и итоговый контроль
* **Отчетность «До / После»:** Для каждого внесенного изменения или оптимизации приводятся измеримые метрики сравнения: сокращение объема кода, уменьшение числа запросов к базе данных, снижение времени выполнения, оптимизация размера контейнеров или потребления ресурсов.
* **Итоговая проверка:** После завершения всех фаз выполняется повторный запуск тестов внутри Docker-окружения, проверка логов на ошибки и предоставление итогового отчета по трем категориям.
