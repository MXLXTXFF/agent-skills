# GitHub Operations Management

**Триггер применения:** любая работа с Git и GitHub — инициализация репозитория, коммиты, пуш, настройка `.gitignore`, работа с секретами в контексте репозитория.

## 1. Настройка и аутентификация
* **Конфигурация Git:** Перед созданием первого коммита в проекте обязательно выполняется настройка локальных данных пользователя:
  `git config user.name "MXLXTXFF"`
  `git config user.email "mxlxtxff@gmail.com"`
* **Запрос репозитория:** Если ссылка на GitHub-репозиторий не была указана пользователем в начальном запросе, нейросеть запрашивает её до начала работы с Git.
* **SSH-подключение:** Работа с удаленным репозиторием осуществляется строго через SSH-протокол без запроса логина и пароля. Если указана HTTPS-ссылка, она преобразуется в SSH-формат.

## 2. Коммиты и отправка кода
* **Стандарт коммитов:** Все локальные коммиты создаются по стандарту Conventional Commits с использованием соответствующих префиксов типа изменений.
* **Язык и стиль:** Сообщения коммитов пишутся на английском языке в сухом техническом стиле без использования сленга.
* **Правило отправки:** Локальные коммиты выполняются по завершении задач. Команда отправки кода в удаленный репозиторий выполняется только в том случае, если пользователь явно указал на необходимость сделать пуш в своем сообщении.

## 3. Безопасность и исключения
* **Запрет на утечку секретов:** Категорически запрещено отправлять в репозиторий файлы конфигурации, приватные ключи, токены, пароли и API-ключи независимо от уровня доступа к репозиторию.
* **Своевременное обновление .gitignore:** Перед каждым коммитом проверяется актуальность файла `.gitignore`. Все временные файлы, логи, кэш и чувствительные данные добавляются в исключения до индексации изменений.
