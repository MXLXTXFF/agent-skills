# agent-skills

Библиотека стандартных скиллов для AI-агента (Claude / Claude Code), работающего в чатах по разработке программного обеспечения. Репозиторий не содержит кода — это поведенческая база знаний: набор `.md`-файлов с обязательными правилами, которые агент изучает и применяет вместо поведения по умолчанию.

## Обзор системы

Репозиторий решает одну задачу: перенести повторяющиеся требования пользователя к работе агента (окружение, Git, документация, координация между сессиями, рефакторинг, публичные changelog) из памяти одной чат-сессии в переиспользуемый, версионируемый источник правды, доступный любой сессии на сервере.

```text
Репозиторий agent-skills (Git, GitHub)
  ↓
Локальная копия /srv/agent-skills на сервере
  ↓
Чат-сессия читает skills/*.md по запросу пользователя или по совпадению задачи
  ↓
Правила скилла применяются как обязательные до конца задачи/сессии
```

## Архитектура

- Единица хранения — один скилл на один файл в `skills/`. Файлы не зависят друг от друга и могут применяться по отдельности или одновременно, если задача затрагивает несколько областей.
- Актуальность на сервере поддерживается через `git pull` в `/srv/agent-skills` — все чат-сессии, работающие на этом сервере, используют одну и ту же локальную копию, без отдельного клонирования под каждую сессию.
- Репозиторий публичный: локальная копия остаётся основным путём чтения (быстрее и не требует сети), но при её отсутствии содержимое доступно и без SSH-ключа — через `git clone` по HTTPS или напрямую по сырым GitHub-ссылкам.
- Активация скилла определяется агентом самостоятельно: фронтматтер `description` и раздел `Activation` внутри файла описывают, при каких задачах скилл обязателен. Отдельного реестра или диспетчера нет — соответствие ищется по содержимому файлов.

## Формат скилла

Действующий стандарт (применяется ко всем скиллам, кроме отмеченного в таблице выше):

- Файл открывается YAML-фронтматтером с двумя обязательными полями: `name` (человекочитаемое имя скилла) и `description` (сжатое описание области применения — по нему агент сопоставляет скилл с задачей).
- Тело файла ведётся на английском языке и структурировано разделами: `Purpose` (назначение), `Activation` (условия, при которых скилл обязателен), далее — тематические разделы с конкретными правилами, а где уместно — примеры «плохо/хорошо».
- Раздел `Activation` — это замена более ранней короткой строки «Триггер применения»: то же назначение (агент понимает, когда скилл обязателен, не читая всё целиком), но раскрыто в виде списка конкретных условий вместо одной строки.

## Конфигурация

- **Рабочая директория на сервере:** `/srv/agent-skills` — фиксированный путь, на который ссылаются все промты ниже. При восстановлении отсутствующей копии клонирование выполняется строго в этот же путь, а не в произвольное место.
- **Репозиторий и доступ:** `git@github.com:MXLXTXFF/agent-skills.git` (SSH) — репозиторий публичный, поэтому чтение возможно и без SSH-ключа (HTTPS-клонирование или сырые GitHub-ссылки), но запись (пуш) по-прежнему требует прав доступа.
- **Секреты:** в скиллах не хранятся реальные пароли, токены или ключи — только имена переменных, примеры команд и плейсхолдеры.

## Как использовать

Правила не встроены в агента — их нужно явно скормить в начале (или в середине) любой чат-сессии. Ниже два вида промтов: общий, который сам выбирает нужные скиллы, и короткие промты для принудительного применения одного конкретного скилла. Оба вида — обычный текст без markdown-разметки, так как отправляются как сообщение в чат, а не как файл.

### Универсальный промт

Отправь этот промт в любую чат-сессию с Claude / Claude Code — в новую или уже идущую. Агент сам разберётся, какие скиллы из репозитория относятся к текущей задаче, и будет следовать им до конца сессии.

```
Universal Skills Onboarding

Активируется в начале любой чат-сессии по разработке ПО; повторно — при
явном сообщении о том, что скиллы обновились.

1. Получение содержимого репозитория
- Локальная копия есть: если /srv/agent-skills существует — скачивание не
  требуется, выполняется git pull в этой директории, файлы читаются с диска.
- Локальной копии нет: репозиторий клонируется строго в /srv/agent-skills
  (git clone git@github.com:MXLXTXFF/agent-skills.git /srv/agent-skills;
  при отсутствии SSH-доступа — по HTTPS: git clone
  https://github.com/MXLXTXFF/agent-skills.git /srv/agent-skills), а не в
  произвольный путь.

2. Изучение и выбор скиллов
- Полное чтение: README.md и каждый файл из skills/ прочитываются целиком.
- Сопоставление с задачей: для каждого файла проверяются поле description
  во фронтматтере и раздел Activation (или строка "Триггер применения" у
  файлов, ещё не переведённых на новый формат); скилл применяется, если
  условия совпадают с текущей задачей.
- Комбинирование: если задача затрагивает несколько областей одновременно —
  применяются все подходящие скиллы параллельно.

3. Применение правил
- Приоритет: правила выбранных скиллов обязательны и имеют приоритет над
  поведением по умолчанию до конца сессии — в том числе если сессия уже шла
  до получения этого промта.
- Смена контекста задачи: при смене области работы в рамках одной сессии
  соответствие скиллов проверяется заново без отдельного напоминания.

4. Синхронизация при обновлениях
- Сигнал от пользователя: если пользователь сообщает, что скиллы обновились,
  дополнились или появился новый файл — перед продолжением обязательно
  повторяется git pull в /srv/agent-skills и перечитываются изменившиеся или
  новые файлы.
- Запрет на устаревшую версию: нельзя полагаться на ранее прочитанное
  содержимое файла после получения сигнала об изменениях.
```

## Обновление скиллов

Новые правила и правки добавляются напрямую в `skills/`. Ссылка на репозиторий остаётся неизменной — обновляется только содержимое файлов, поэтому один и тот же универсальный промт продолжает работать после любых изменений.

При добавлении нового скилла обязательно:
1. оформить файл по актуальному стандарту — фронтматтер `name`/`description`, разделы `Purpose`/`Activation` и далее правила (см. [Формат скилла](#формат-скилла));
2. добавить файл в дерево в разделе [Структура проекта](#структура-проекта) и строку в таблицу [Компоненты](#компоненты);
3. добавить для него короткий промт в раздел [Промты для конкретного скилла](#как-использовать) по тому же шаблону (Skill / File / текст с git pull и путём до файла).
