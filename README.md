# agent-skills

Набор стандартных правил (скиллов) для работы AI-агента (Claude / Claude Code) в чатах, посвящённых разработке программного обеспечения. Скиллы описывают, как агент должен вести себя при работе с окружением, Git/GitHub, документацией и разработкой сервисов — независимо от конкретного проекта.

Репозиторий — не код, а поведенческая база знаний: набор `.md`-файлов, которые агент обязан изучить и применять как обязательные правила, переопределяющие поведение по умолчанию.

## Структура

```
agent-skills/
└── skills/
    ├── environment-configuration-management.md   # .env, .env.example, переменные окружения, именование
    ├── github-operations-management.md           # Git/GitHub: аутентификация, коммиты, пуш, безопасность
    ├── project-documentation-and-agent-memory.md  # README.md и AGENT.md — правила ведения и синхронизации
    └── project-and-service-development.md         # архитектура, БД, Docker, тестирование, коммуникация
```

Каждый файл в `skills/` начинается со строки **«Триггер применения»** — она описывает, в каком контексте работы этот скилл становится обязательным. Агент использует эти триггеры, чтобы понять, какие скиллы актуальны для текущей задачи, не читая и не применяя лишнего.

## Как это использовать

Правила не встроены в агента — их нужно явно скормить в начале (или в середине) любой чат-сессии. Для этого ниже есть универсальный промт. Он повторяет ту же структуру, что и файлы в `skills/` — заголовок, строка триггера, нумерованные разделы с подписанными пунктами, — но без markdown-разметки, потому что отправляется как обычный текст сообщения, а не как файл.

### Универсальный промт

Отправь этот промт в любую чат-сессию с Claude / Claude Code — в новую или уже идущую. Агент сам разберётся, какие скиллы из репозитория относятся к текущей задаче, и будет следовать им до конца сессии.

```
Universal Skills Onboarding

Триггер применения: начало любой чат-сессии по разработке ПО; повторное
применение — при явном сообщении о том, что скиллы обновились.

1. Получение содержимого репозитория
- Локальная копия есть: если /srv/agent-skills существует — скачивание не
  требуется, выполняется git pull в этой директории, файлы читаются с диска.
- Локальной копии нет: репозиторий клонируется строго в /srv/agent-skills
  (git clone git@github.com:MXLXTXFF/agent-skills.git /srv/agent-skills),
  а не в произвольный путь.
- Приватность репозитория: доступ возможен только через SSH-ключ с правами
  на этот репозиторий; анонимное чтение по HTTPS/raw-ссылкам недоступно.

2. Изучение и выбор скиллов
- Полное чтение: README.md и каждый файл из skills/ прочитываются целиком.
- Сопоставление по триггерам: для текущей задачи выбираются все скиллы, чья
  строка «Триггер применения» соответствует контексту работы.
- Комбинирование: если задача затрагивает несколько областей одновременно —
  применяются все подходящие скиллы параллельно.

3. Применение правил
- Приоритет: правила выбранных скиллов обязательны и имеют приоритет над
  поведением по умолчанию до конца сессии — в том числе если сессия уже шла
  до получения этого промта.
- Смена контекста задачи: при смене области работы в рамках одной сессии
  триггеры проверяются заново без отдельного напоминания.

4. Синхронизация при обновлениях
- Сигнал от пользователя: если пользователь сообщает, что скиллы обновились,
  дополнились или появился новый файл — перед продолжением обязательно
  повторяется git pull в /srv/agent-skills и перечитываются изменившиеся или
  новые файлы.
- Запрет на устаревшую версию: нельзя полагаться на ранее прочитанное
  содержимое файла после получения сигнала об изменениях.
```

### Важно

- Основной путь — локальный диск: все чат-сессии на одном сервере используют уже существующую копию в `/srv/agent-skills`, обновляя её через `git pull`. Клонирование — это fallback на случай отсутствия локальной копии, а не обязательный шаг.
- Репозиторий приватный: анонимный запрос к `raw.githubusercontent.com` или GitHub API возвращает 404. Прочитать содержимое можно только с локальной копии или клонированием по SSH-ключу с доступом к репозиторию.
- Промт одинаково работает и для чистой сессии, и для сессии, где работа уже идёт — агент обязан подтянуть правила «задним числом» и следовать им дальше.
- Скиллы читаются целиком при каждом запросе на обновление — агент не должен полагаться на память о старой версии файла после того, как получил сигнал об изменениях.
- Обновление или добавление скилла в этом репозитории не требует ничего, кроме коммита в `skills/` — все существующие чат-сессии подтянут изменения по сигналу «скиллы обновились» без повторной настройки.

## Обновление скиллов

Новые правила и правки добавляются напрямую в `skills/`. Ссылка на репозиторий остаётся неизменной — обновляется только содержимое файлов, поэтому один и тот же универсальный промт продолжает работать после любых изменений.
